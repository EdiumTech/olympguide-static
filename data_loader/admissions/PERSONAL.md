# Стипендии, календарь и проверка дипломов

Дополнение `personal-2026-20260908` использует основной каталог приёма 2026 и
дополнение с местами/стоимостью. В Git находятся код, тесты и манифест
`releases/2026-personal.json`. JSON, HTML, PDF и извлечённый текст упакованы в ZIP
GitHub Release. До публикации Release можно установить локальный ZIP через
`--archive`; URL из манифеста станет доступен после публикации.

## Данные и границы проверки

`amount_min`/`amount_max` и неизвестный учебный год остаются `null`.

Оригиналы источников и SHA-256 находятся в архиве. Для публикации МАИ
`https://mai.ru/press/news/detail.php?ID=175763` сохранён текст официальной страницы,
полученный из поискового индекса: прямое получение HTML не удалось.
Это явно отмечено `capture_type=indexed_official_page` и `retrieval_note` в метаданных;
такой файл не представляется оригинальным HTML.

Стипендия, разовый грант/премия и скидка имеют разные `kind` и `frequency`.
Рекламный годовой максимум не пересчитывается в гарантированную месячную выплату.
Совместимость указывается только при подтверждении. Выплаты кампуса не наследуются
программой только по принадлежности вузу: нужны явные `scope.program_keys`.
На странице вуза показаны все записи с их областью действия; на программе — только
подтверждённые для неё, с переходом к остальным сведениям вуза.

Календарь содержит 8 записей: общий график «Высшей пробы» 2026/27 (регистрация,
два тура отбора, финал, результаты и апелляции с **неизвестными** сроками), а также
окончание подачи документов на бюджет ИТМО 25.07.2026. Для анализа данных и
промышленного программирования общий график не назначается. Точные расписания
других олимпиад/профилей ещё не подтверждены. Собственные события поддерживаются
без заявления об официальной проверке. Push, APNs, запросы разрешений и фоновые
уведомления не реализованы.

## Расчёт льгот

Существующие дипломы сохраняются. Дополнены год получения, учебный год олимпиады,
профиль, результат; отдельно на пользователе хранятся год поступления и ЕГЭ.
Старые записи не получают выдуманных значений. `level` сохраняет старый формат
I/II/III; это степень диплома, не уровень олимпиады. Класс — класс выполнения заданий.

`eligibility_rules.py` разбирает только проверенные грамматики и пары
«название — профиль». Неизвестная сноска, неподдержанная оговорка, подозрительное
сочетание из прежнего импорта или изменившийся источник переводят правило в
ручную проверку. Исходная формулировка и ссылка всегда сохраняются.
В текущем наборе 8 163 разбора: 1 006 полностью проверяемых и 7 157
с ручной проверкой. Это число вариантов правил, а не число программ или
абитуриентов с правом на зачисление.
В частности, автоматическая проверка не доверяет перенесённому названию
«Формула Единства» рядом с технологическими профилями НТО в старом извлечении МГТУ.
Исправление этих исходных строк требует отдельного пересмотра основного Release.

БВИ и 100 баллов проверяются независимо. Для МФТИ условия конкурсной группы,
степени диплома и порога 75/80/85 остаются связанными; принадлежность школе сама
по себе не даёт льготу. «Все конкурсные группы школы» учитывается только при такой
прямой формулировке источника. Не разобранные исключения за 10 класс и внутренние
вступительные испытания требуют ручной проверки. Пониженный порог 65 баллов и
продление срока диплома для специальных категорий не превращаются в отказ.
Для программ на базе предыдущего образования требуется дополнительная проверка.

Статусы API: `eligible`, `confirmation_required`, `ineligible`, `manual_review`.
У каждой оценки есть причина, результаты отдельных условий и исходное правило.
Статус программы показывает лучший доступный вариант; отдельные правила могут
иметь разные статусы. Положительный статус означает соответствие **введённым**
данным, а документы и зачисление проверяет вуз. Это не гарантия зачисления.
ВсОШ, международные олимпиады, МАИ, сложные исключения и неподтверждённые пары
в этой версии преимущественно остаются в ручной проверке.
Для приёма 2027 правила 2026 не используются.

## Установка и обновление

Из корня static-репозитория:

```console
python -m data_loader.admissions download
python -m data_loader.admissions download-quantities
python -m data_loader.admissions.personal download
python -m data_loader.admissions.personal validate
python web/server.py
```

До публикации вместо третьей команды:
`python -m data_loader.admissions.personal download --archive tmp/releases/olympguide-personal-2026-20260908.zip`.
Загрузчик проверяет SHA-256 архива и каждого файла, отклоняет опасные пути и
сохраняет изменённый локальный снимок. `build` сверяет оригиналы и базовые манифесты;
`package` формирует архив и новый манифест. После редакторской проверки новых
источников изменяются факты в Python, затем выполняются `build` и `package`.

Для backend нужны миграции 017–019 и основной импорт 2026. Развивается существующий
`deploy/import_admissions.py --personal-only`, отдельная ветка загрузчика не нужна:

```console
python deploy/import_admissions.py --static-repo ../olympguide-static --personal-only --output .private/personal-2026.sql
```

Дополнение импортируется **после** основного каталога. Основной импорт удаляет
старые разборы через FK; до повторного импорта дополнения API показывает ручную
проверку. Несовпадение исходного правила прерывает транзакцию импорта.

ID события не содержит дату. Обновление меняет общий источник, сохраняя личные
статус/заметку/подтверждённую ревизию. Повторное добавление идемпотентно. Удалённые
из полного списка коллекции события помечаются неактивными, а личные планы остаются.
Пустой список явно названной коллекции снимает все её события. Неупомянутые
коллекции не затрагиваются.

`timed` хранит RFC3339 + IANA timezone; `all_day` — дату без фиктивной полуночи;
`date_range` включает обе календарные даты; `undated` не содержит дат.
Интервалы точного времени имеют исключающую правую границу. Переход DST не
предполагает 24 часа в каждом календарном дне. В веб-форме повторяющееся при
переводе часов время нужно указать в UTC, чтобы устранить неоднозначность.

## Проверки

Из корня static: `PYTHONPATH=data_loader:. python -m unittest discover -s data_loader/admissions/tests -v`,
`python -m unittest discover -s web/tests -v`, `node web/tests/test_personal_dates.js`.
В PowerShell: `$env:PYTHONPATH='data_loader;.'`.
Для теста настоящего импорта дополнительно задаются `OLYMPGUIDE_TEST_DSN` и `PSQL`
(путь к psql) на отдельную мигрированную тестовую БД.

В backend: `go test ./...` из `api`; интеграционные тесты используют
`OLYMPGUIDE_TEST_DSN` и загруженные основной/дополнительный наборы.
Для macOS со Swift/Xcode: `sh iOS/scripts/test-network.sh`,
`sh iOS/scripts/test-personal.sh` и сборка приложения. На Windows эти Swift-тесты
и сборка iOS не выполнены: Xcode отсутствует.
